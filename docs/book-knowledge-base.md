# 全书知识库与管理员加工工作台

## 1. 目标与边界

每本书上架前必须完成全书级加工。Agent 需要理解全书结构、作者主张、论证关系和章节思想脉络，不能只依赖当前段落的临时检索。

知识库不是一本书的摘要，也不只是向量索引。它是由原文支撑、可追溯、可供 Agent 全局理解和局部精读的结构化知识资产。

**原文是知识库的根；所有解释、摘要、关系和推导都必须回到原文证据。**

同一 BookRevision 的知识库是公共资产，可供获得该版本访问权的用户复用。用户对话、笔记和认知记忆不得进入公共知识库。

## 2. 六层知识结构

### 2.1 原书结构
全书、篇章、章节、小节、论述单元。保留作者目录和顺序；论述单元按语义完整性拆分，不按固定字数切割。

### 2.2 核心思想
记录章节要解决的问题、核心主张、关键结论和该章节在全书中的作用。

### 2.3 论证体系
记录主张、推理步骤、论据、案例、证据、反例和结论之间的关系。区分作者明确陈述与加工模型的归纳。

### 2.4 概念体系
记录重要概念、作者定义、上下文含义、同义/近义概念、上下位关系、对立关系和概念变化。

### 2.5 章节思想关系
记录章节之间的承接、补充、递进、对照、矛盾和依赖关系。每条关系必须有原文依据或明确标记为待验证推断。

### 2.6 精读辅助信息
记录理解难点、容易误解之处、关键推理环节和可供讨论的现实联系。这些是 Agent 的内部参考，不是必须推送给用户的问题清单。

## 3. 最小知识对象

每条知识对象至少保存：knowledge_item_id、book_revision_id、structure_node_id、item_type、content、source_chunk_ids、source_locator、extraction_method、model_version、confidence、review_status 和时间戳。

建议类型：chapter_intent、thesis、key_point、concept、argument、evidence、case、counterargument、chapter_relation、reading_difficulty。

所有对象都必须能追溯到一个或多个原文切片。无来源的生成内容不得作为作者事实展示。

## 4. 加工流水线

1. 上传与识别：管理员上传原始文件，识别格式、元数据、语言和版本。
2. 原文解析：抽取正文、目录、标题、段落、页码、脚注、图表等；保留原文件和内容哈希。
3. 结构识别：识别篇章、章节、小节和语义完整论述单元。
4. 原文切片：建立 chunk 与结构节点映射，保留精确定位。
5. 思想提取：提取章节意图、核心主张、概念、论证、证据和案例。
6. 关系构建：识别章节之间的思想关系，形成全书论述地图。
7. 精读辅助加工：标记难点、易误解内容和关键推理节点。
8. 质量检查：自动执行覆盖率、定位、来源、关系和一致性检查。
9. 管理员验收：检查异常项、修正结构或知识项，确认发布。
10. 发布：知识库与具体 BookRevision 一起发布，形成不可变版本。

## 5. 质量验收

不以单一百分制决定是否可发布。

| 检查项 | 验收要求 |
|---|---|
| 原文完整性 | 目录和正文无明显缺失、重复或错序 |
| 结构准确性 | 章节层级与作者原书基本一致 |
| 论述单元 | 边界语义完整，能独立呈现和定位 |
| 原文定位 | 每个单元可回查原文 |
| 观点可追溯 | 作者主张有直接原文证据 |
| 论证完整性 | 重要推理、论据和案例没有明显遗漏 |
| 概念准确性 | 定义和语境有原文依据 |
| 章节关系 | 重要关系有证据，推断与事实区分 |
| Agent 可用性 | 能按主线获取原文并检索全书关系 |

报告状态分为通过、警告、失败。失败项必须能定位到章节、页码、结构节点或 chunk。

## 6. 管理员加工工作台

工作台以“书籍任务”为中心，第一版不做复杂内容运营系统。

### 6.1 书籍列表
展示书名、作者、版本、加工状态、质量状态、发布时间和最近更新时间。

### 6.2 上传与版本
支持上传原始文件、录入/修正元数据、创建新 BookRevision。新版本不覆盖旧版本。

### 6.3 加工详情
提供原书结构、原文查看、核心思想、论证体系、概念体系、章节关联、精读辅助和质量报告等视图。

### 6.4 修正能力
管理员可以调整章节/论述单元边界、修正元数据、修订错误知识项、标记无法确认的关系。修改必须留有操作记录，重新加工时不得静默覆盖人工修正。

### 6.5 发布控制
只有加工完成且质量检查达到发布条件，管理员确认后才能上架。发布后该 BookRevision 与知识库版本不可变；修改应创建新的修订版本。

### 6.6 权限
管理员只管理公共书籍和知识库。不得在工作台展示用户私人 Thread、Message、Note 或 Memory。

## 7. 失败与返工

- 每个阶段记录输入哈希、处理器版本、输出哈希、状态、耗时和错误。
- 失败报告给出可定位的问题和建议重做阶段。
- 输入与规则未变化的已通过阶段可复用缓存。
- 影响原文、结构或知识内容的返工生成新的加工尝试；正式发布版本不可原地改写。
- 云端保留从原始书籍文件重新解析和重建知识库的能力。

## 8. 与 Agent 的调用关系

Agent 按需获取当前主线原文、章节核心思想和论证链条、相关概念和章节关系。用户主动提出跨章节问题时，再检索所需的相关知识项。

知识库帮助 Agent 理解全书，但不能替代原文展示。回答作者观点时必须能够引用原文；模型推演和补充解释要明确区分。

## 9. 版本与隔离

- BookKnowledgeBase 必须绑定 BookRevision。
- 新 BookRevision 创建新的结构、切片、知识库和索引。
- 旧版本知识库保留，供历史 Thread 和 Citation 追溯。
- 公共知识库可以跨用户复用；私人认知数据不得进入公共知识库。
