# 阅读 Agent 交互与主线机制

## 1. 产品角色

第一版只有一个默认阅读 Agent。它不是主动教学系统，不负责监督、打分或考试，而是围绕作者原文与用户进行长期讨论的阅读伙伴。

多角色模式暂不纳入第一版；未来如需不同角色，再独立设计。

## 2. 原文呈现

- Agent 根据作者目录和论述逻辑，按语义完整的论述单元提供原文。
- 不按固定字数切割，不用摘要替代原文。
- 一个单元展示完成后，等待用户发言。
- 不主动推送问题、提示卡、测验、提醒或下一段内容。
- 用户可要求重新展示当前或已读原文。

## 3. 阅读界面

- 上方：原文区，可折叠，展示当前论述单元及章节定位。
- 下方：讨论区，展示用户与 Agent 的连续对话。
- 用户讨论时可以重新展开原文，确保随时查看讨论依据。
- 原文展示记录和讨论消息保持关联；折叠只改变显示状态，不改变阅读主线。

## 4. 讨论原则

- 用户发言后，Agent 根据实际表达回应、解释、启发、追问或辩论。
- 不对用户理解程度打分，不组织考试，不设置理解达标门槛。
- 用户赞同、反对、质疑作者均可；准确理解作者但反对作者也是有效讨论。
- Agent 不必判断用户是否真正理解，只需针对当前表达提供有价值的回应。
- 用户没有发言时，Agent 不催促、不自动续写。

## 5. 主线推进

- 主线按作者原书章节、节和论述单元顺序推进。
- 用户主动要求继续时，展示下一主线单元。
- 不允许跳过主线内容。
- 用户已理解且不想深入讨论时，可以简要回应并略读，但仍需经过该主线单元。
- 不通过分数或考试判断讨论充分程度；主线推进由用户主动要求继续触发。

## 6. 复习与临时查看

- 用户可随时要求重新展示已读原文，属于复习。
- 用户可因讨论关联要求展示其他章节或后续内容，属于临时查看。
- 复习和临时查看都记录来源与展示行为，但不修改当前主线位置、不创建新 Thread 或新阅读轮次。
- 临时查看结束后，用户可继续当前主线；Agent 不擅自跳转主线。

## 7. 阅读轮次完成

一轮完成条件：
- 作者原书的所有主线章节和论述单元均已展示。
- 用户对主线内容均有机会进行讨论；用户可以简短回应或主动略读，不要求达到某种理解评分。
- 最后一个主线单元已由用户主动推进并完成讨论。

完成后，Agent 可以说明本轮主线已完成，并询问用户是否开启下一轮。不开启则保持 Thread 历史，不自动重置。

## 8. 数据记录

原文展示记录至少包含 BookRevision、StructureNode、Chunk、展示类型（主线/复习/临时查看）、阅读轮次和时间。临时查看不得覆盖 ReadingRoundState。

## 9. 不做的事情

- 不主动推送阅读问题或下一段原文。
- 不催促用户发言。
- 不打分、不考试、不评估理解水平。
- 不自动跳过主线。
- 不因临时查看而更改主线位置。
- 第一版不引入多角色 Agent。
