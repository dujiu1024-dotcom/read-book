# 知行 PC Web 技术 PoC 验证计划

> 状态：待执行。当前仓库没有知行业务实现，因此不能把本文件中的测试项标记为已通过。
> 验证对象：独立技术 PoC，不包含知行正式业务页面、业务 API 或生产数据库迁移。

## 1. 验证目标
1. 确定 IndexedDB 与 SQLite WASM + OPFS 哪个更适合本地优先的关系型阅读数据。
2. 验证浏览器关闭、崩溃、Worker 重启和多标签页竞争后的数据完整性。
3. 验证 Web Crypto 备份加密、独立恢复凭证、分块上传和恢复流程。
4. 验证 EPUB/PDF/TXT 导入、文件缓存、阅读定位能力。
5. 验证浏览器流式输出中断后，服务端生成任务和最终结果能否恢复。
6. 明确 Chrome/Edge 主测环境与 Firefox/Safari 的兼容边界。

## 2. 验证环境矩阵

| 环境 | 角色 | 必测内容 |

| 当前稳定版 Chrome 桌面端 | P0 主测 | 全部测试 |
| 当前稳定版 Edge 桌面端 | P0 主测 | 全部测试 |
| 当前稳定版 Firefox 桌面端 | P1 兼容 | IndexedDB、OPFS、Worker、Web Crypto、持久化 |

## 3. PoC A：IndexedDB 对照组

测试内容：
- 建立与正式数据模型规模接近的对象仓库和索引。
- 测试多对象仓库读写事务、事务中断、版本升级和索引重建。
- 写入 1 万、10 万、50 万条消息记录，包含短消息、长 Markdown、引用和来源关系。
- 测试批量导出一致性快照、导入恢复、增量变更日志。
- 测试多标签页同时读写和版本升级阻塞处理。
- 测试浏览器关闭/崩溃后数据完整性。

观察指标：
- 单条写入 P50/P95。
- 1k/10k 消息查询耗时。
- 备份快照耗时和内存峰值。
- 数据迁移耗时。
- 事务失败率和数据完整性。
- 多标签页阻塞/冲突情况。

## 4. PoC B：SQLite WASM + OPFS

测试内容：
- 官方 SQLite WASM，在 Worker 内初始化数据库。
- 分别测试官方 OPFS VFS 与 opfs-wl；如有必要才将 opfs-sahpool 作为性能对照，不作为默认方案。
- 创建正式数据模型核心表、外键、唯一约束和索引。
- 测试事务、并发写、长文本、复杂关联查询、全文检索候选。
- 测试 Worker 崩溃、浏览器强制退出、页面刷新和设备重启后的数据库恢复。
- 测试两标签页同时打开同一数据集：锁竞争、只读降级、owner 交接和异常恢复。
- 测试数据库一致性检查、备份导出、恢复导入和 schema migration。
- 测试 OPFS 配额耗尽和浏览器拒绝 persist()。

观察指标：
- 事务提交 P50/P95。
- 消息列表、来源追溯、认知演变查询耗时。
- 1 万/10 万/50 万消息规模下的内存和文件体积。
- 数据库完整性检查结果。
- Worker 崩溃后可恢复比例。
- 多标签页锁冲突、SQLITE_BUSY 次数和恢复时间。
- VFS 初始化失败率及浏览器差异。

## 5. PoC C：备份加密与恢复

必测用例：
1. 首次全量备份。
2. 少量消息变更后的增量备份。
3. 多次增量后完整检查点。
4. 上传中断后断点续传。
5. 同一 backup init/complete 请求重复提交。
6. 单个密文块损坏、manifest 哈希错误、父链缺失。
7. 恢复凭证错误、丢失、格式损坏。
8. 账号注销后使用独立恢复凭证恢复。
9. 数据集清除后使用旧下载票据、恢复票据和旧 URL 访问。
10. 上传与清除并发，清除墓碑优先。
11. 恢复时本地已有另一个数据集，确认不覆盖、不合并。
12. 旧版本备份恢复到新版本客户端。

通过标准：
- 任一密文被篡改都必须在恢复前被发现。
- 错误恢复凭证不能得到可读明文。
- 备份服务端无法通过管理接口解密内容。
- 恢复失败不得破坏当前本地数据。
- 重复请求不产生重复备份或重复数据。
- 清除墓碑建立后，任何新旧授权均不能恢复该数据集。
- 备份和恢复过程中不得把私人正文写入服务端日志。

## 6. PoC D：文件导入与阅读

样本至少包括：
- EPUB：目录层级完整、图片、脚注、章节锚点。
- PDF：可复制文本、双栏排版、页眉页脚、脚注、扫描件/OCR。
- TXT：编码差异、无目录、长段落。

验证：
- 文件选择与导入大小限制。
- 原文件哈希、解析版本、章节树和原文定位。
- EPUB CFI 或稳定定位标识。
- PDF 页码、文本片段定位与回跳。
- 浏览器关闭后已缓存内容可离线打开。
- 大文件解析不阻塞 UI 主线程。
- 缓存清理不删除用户对话和笔记来源。

## 7. PoC E：对话流式与任务恢复

先使用模拟服务端 GenerationJob，不连接真实模型也可验证协议：
- 消息本地先落库。
- 创建 generation_id。
- 事件按 event_id/sequence 递增。
- 页面刷新或断网后任务继续运行。
- 重新连接后查询状态和最终结果。
- 用户取消与自然完成竞态。
- 同一 idempotency_key 重复提交。
- Worker/服务进程崩溃后任务恢复。
- 代理缓冲和长时间无 token 时心跳行为。

最终结果必须可通过 GET generation 查询，不依赖客户端一直保持 SSE/fetch 流连接。

## 8. PoC F：存储配额与持久化
- 调用 navigator.storage.estimate() 记录 usage/quota。
- 请求 navigator.storage.persist()，记录 granted/denied。
- 测试接近配额上限时的写入异常和错误提示。
- 测试浏览器低磁盘、无痕模式和用户主动清理站点数据。
- 验证配额失败不会造成半提交事务或覆盖旧备份。
- 设计本地缓存分级：核心私人数据、已加入书架原文缓存、可重下载资源、临时缓存。
- 不允许自动删除用户私人消息、笔记或认知记录来腾空间。

## 9. 测试数据规模
- S：1,000 条消息、1 本书、100 条笔记/记忆。
- M：100,000 条消息、20 本书、5,000 条笔记/记忆。
- L：500,000 条消息、100 本书、20,000 条笔记/记忆。
- 文件数据单独建立 50 MB、200 MB、500 MB 三档样本；实际阈值根据浏览器配额与性能结果调整。以上规模是压力测试样本，不是产品容量承诺。

## 10. 结果记录格式
每个用例记录 Case ID、PoC commit、浏览器/版本/操作系统、测试数据规模、步骤与预期、实际结果、日志/截图/数据库校验、P50/P95、内存峰值、存储用量、通过/失败/阻塞/未执行、问题归属和修复建议。

## 11. 阶段性决策门槛
- Gate A：本地数据库选型。数据一致性、崩溃恢复和迁移必须通过，性能其次。
- Gate B：备份安全。篡改检测、恢复凭证、清除墓碑和恢复保护必须通过。
- Gate C：文件阅读。样本解析和定位必须达到可接受基线。
- Gate D：对话可靠性。断线不丢最终结果，取消和幂等语义确定。
- Gate E：浏览器支持。明确主测和降级/不支持矩阵。
未完成 Gate A/B 前，不应开始承载真实用户私人数据的业务开发。
