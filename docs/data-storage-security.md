# 本地数据、加密备份与账号分离

## 1. 已确认的数据原则

- 用户个人阅读数据以本地设备为主存储。
- 服务器只保存加密备份，不作为用户个人数据的在线主库。
- 换账号不自动迁移、同步或合并数据；需要时由用户通过备份下载流程恢复到本地。
- 账号注销只删除账号身份，不删除本地数据或服务器备份。
- 用户数据与账号身份分离；账号不是数据资产的唯一容器。

## 2. 数据范围

本地数据包括书架条目和版本权益、Thread、Message、原文展示和临时查看记录、阅读轮次、笔记、认知记忆及来源关系、用户设置和备份状态。

服务器端只保存账号认证信息、公共书籍和全书知识库、加密备份密文及索引、下载授权记录。模型请求所需的短暂上下文不属于备份主库。

## 3. 本地存储

具体采用 SQLite、IndexedDB 或平台原生存储需经目标平台验证。必须验证事务与崩溃恢复、容量、长文本性能、文件访问、数据迁移、数据库加密和密钥安全存储。

本地数据是主副本，客户端应明确显示最近备份时间和状态。设备丢失或卸载可能造成未备份数据丢失，必须明确告知用户。

## 4. 加密备份

1. 本地生成一致性快照。
2. 按版本化备份包格式导出数据。
3. 使用用户独立恢复密钥在本地加密。
4. 上传密文和最小必要 manifest。
5. 服务端校验大小、哈希、格式版本和密文完整性。
6. 服务端保存多个历史备份版本，不覆盖唯一副本。

服务器不得持有可直接解密用户备份的明文密钥，也不得提供管理员解密入口。

## 5. 恢复与换账号

- 恢复可发生在新设备或新账号下。
- 恢复凭证独立于账号密码；账号注销后仍能授权下载和解密原备份。
- 换账号时不自动迁移数据。用户主动进入恢复流程，验证恢复凭证，下载密文到本地并解密。
- 恢复前先保护当前本地数据，避免覆盖。
- 恢复完成后，本地数据仍是主存储；是否为新账号创建新的备份关联需用户明确操作。
- 不提供静默的账号间数据合并。

## 6. 账号注销

账号注销执行：删除账号身份和认证凭证，解除第三方平台身份映射，停止该账号新的认证与在线服务访问。

账号注销不得执行：删除本地数据库、删除服务器加密备份、删除用户恢复凭证，或级联删除用户历史对话、笔记和认知记录的备份数据。

注销后用户可凭独立恢复凭证取回备份。账号注销与数据销毁是两个不同动作；本项目当前只确认注销不删除数据。未来若提供数据销毁能力，必须单独设计授权、确认和审计流程。

## 7. 风险控制

| 风险 | 设计控制 |
|---|---|
| 设备丢失 | 本地加密、定期备份、恢复凭证 |
| 备份服务泄露 | 端到端加密，服务端仅持密文 |
| 恢复凭证丢失 | 明确不可恢复风险，提示用户安全保存 |
| 备份被未授权下载 | 短时授权、恢复凭证验证、访问审计 |
| 备份文件损坏 | 哈希校验、多版本保留、定期恢复演练 |
| 应用升级破坏数据 | schema_version、迁移前快照、回滚策略 |
| 账号注销误删数据 | 注销流程与备份生命周期解耦 |
| 模型调用泄露上下文 | 最小化传输、服务商条款审查、日志脱敏 |

## 8. 尚待技术验证

- 小程序本地数据库是否具备足够容量、可靠事务和安全密钥能力。
- 加密数据库、加密备份的算法与实现库。
- 恢复密钥的生成、展示、保存和轮换。
- 备份全量/增量策略和历史版本保留。
- 账号注销后备份的恢复授权和反滥用机制。
- 多设备恢复同一备份后的数据分叉处理。
- 云端模型调用的数据处理、留存和训练政策。

在验证完成前，不得声称已经实现端到端加密、可靠备份或注销后恢复。
