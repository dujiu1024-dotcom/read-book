# 本地数据、加密备份与账号分离

## 1. 已确认的数据原则

- 用户个人阅读数据以本地设备为主存储。
- 服务器只保存加密备份，不作为用户个人数据的在线主库。
- 换账号不自动迁移、同步或合并数据；用户可在主动进入恢复场景时，凭独立恢复凭证在新账号下恢复原有数据集。该能力不在常规前台显眼展示，也不主动宣传。
- 账号注销只删除账号身份，不删除本地数据或服务器备份。
- 用户主动清除个人数据时，本地数据删除；服务器原始备份及密钥材料保持不动，仅软删除用户关联索引和可用授权。
- 用户数据与账号身份分离；账号不是数据资产的唯一容器。

## 2. 数据范围

本地数据包括书架条目和版本权益、Thread、Message、原文展示和临时查看记录、阅读轮次、笔记、认知记忆及来源关系、用户设置和备份状态。

服务器端只保存账号认证信息、公共书籍和全书知识库、加密备份密文及必要索引、下载授权记录。用户清除个人数据后，备份密文及其他原始数据保持不变；仅将用户关联索引和可用授权软删除/失效化。模型请求所需的短暂上下文不属于备份主库。

## 3. 本地存储

具体采用 SQLite、IndexedDB 或平台原生存储需经目标平台验证。必须验证事务与崩溃恢复、容量、长文本性能、文件访问、数据迁移、数据库加密和密钥安全存储。

本地数据是主副本，客户端应明确显示最近备份时间和状态。设备丢失或卸载可能造成未备份数据丢失，必须明确告知用户。

## 4. 加密备份

- 每次应用打开/启动时触发一次备份检查；若存在尚未备份的本地变更，则执行备份。若数据未变化，可快速确认无需重复上传。
- 设备已有本地数据时，按本地变更执行增量备份；增量备份仅针对同一设备/同一数据集，不代表跨设备同步。
- 离线、网络不可用或备份失败时，不阻断应用启动和本地阅读；保留待备份状态，并在后续网络可用时补做。

备份流程：

1. 本地生成一致性快照。
2. 按版本化备份包格式导出数据。
3. 使用用户独立恢复密钥在本地加密。
4. 上传密文和最小必要 manifest。
5. 服务端校验大小、哈希、格式版本和密文完整性。
6. 服务端保存多个历史备份版本，不覆盖唯一副本。

服务器不得持有可直接解密用户备份的明文密钥，也不得提供管理员解密入口。

## 5. 恢复与换账号

- 第一版不做多设备实时同步。
- 新设备首次打开且本地没有知行数据时，提示用户是否从已有备份恢复；用户可以选择暂不恢复。
- 恢复可发生在新设备或新账号下。
- 恢复凭证独立于账号密码；账号注销后仍能授权下载和解密原备份。
- 换账号时不自动迁移数据。用户主动进入恢复流程，验证恢复凭证，下载密文到本地并解密。常规前台不设置显眼的恢复旧账号入口，也不主动宣传该能力。
- 恢复前先保护当前本地数据，避免覆盖。
- 恢复完成后，本地数据仍是主存储；是否为新账号创建新的备份关联需用户明确操作。
- 不提供静默的账号间数据合并。

## 6. 账号注销

账号注销执行：删除账号身份和认证凭证，解除第三方平台身份映射，停止该账号新的认证与在线服务访问。

账号注销不得执行：删除本地数据库、删除服务器加密备份、删除用户恢复凭证，或级联删除用户历史对话、笔记和认知记录的备份数据。

注销后用户可凭独立恢复凭证取回备份。账号注销与数据销毁是两个不同动作；本项目当前只确认注销不删除数据。未来若提供数据销毁能力，必须单独设计授权、确认和审计流程。

## 7. 清除个人数据（软删除）

- 用户主动确认清除个人数据后，客户端删除当前设备上该数据集的个人阅读数据。
- 服务器端不物理删除、不改写加密备份密文，不销毁解密密钥或其他原始数据。
- 服务端将数据集标记为 `cleared` / `inactive`，并对用户关联索引、备份清单可用关联、下载授权和恢复授权执行软删除或失效化。
- 已清除数据集不得通过常规接口读取、检索、下载、恢复、重新授权或重新关联；所有相关接口必须检查数据集状态。
- 软删除状态需要保留审计记录，不能因账号重新注册、登录或普通数据修复流程自动恢复。
- 本操作不等同于物理销毁；服务器保留的原始数据不参与后续业务使用。

## 8. 离线能力

- 离线可查看本地已缓存的书籍原文、历史对话、读书笔记、认知记录及已有阅读信息。
- AI 对话、跨章节智能检索和获取尚未缓存的内容需要联网。
- 离线编辑先写入本地，联网后再执行备份；网络或备份失败不得阻断本地阅读。

## 9. 风险控制

| 风险 | 设计控制 |
|---|---|
| 设备丢失 | 应用打开时触发备份检查、增量备份、恢复凭证 |
| 备份服务泄露 | 端到端加密，服务端仅持密文 |
| 恢复凭证丢失 | 明确不可恢复风险，提示用户安全保存 |
| 备份被未授权下载 | 短时授权、恢复凭证验证、访问审计 |
| 备份文件损坏 | 哈希校验、多版本保留、定期恢复演练 |
| 应用升级破坏数据 | schema_version、迁移前快照、回滚策略 |
| 账号注销误删数据 | 注销流程与备份生命周期解耦 |
| 清除个人数据后仍被访问 | 数据集软删除状态、关联索引失效、授权失效和接口统一拦截 |
| 账号切换后串用本地数据 | 数据集与账号上下文显式隔离，切换不自动迁移或合并 |
| 模型调用泄露上下文 | 最小化传输、服务商条款审查、日志脱敏 |

## 10. 尚待技术验证

- 小程序本地数据库是否具备足够容量、可靠事务和安全密钥能力。
- 加密数据库、加密备份的算法与实现库。
- 恢复密钥的生成、展示、保存和轮换。
- 启动时备份检查的性能、增量备份策略和历史版本保留。
- 账号注销后备份的恢复授权和反滥用机制。
- 第一版不做多设备同步；仍需验证同一备份在不同设备恢复时的冲突保护与数据集边界。
- 云端模型调用的数据处理、留存和训练政策。

在验证完成前，不得声称已经实现端到端加密、可靠备份或注销后恢复。


## 11. PC Web 浏览器存储与安全补充（2026-11-13）

第一阶段 PC Web 的详细方案见 [PC Web 详细技术设计](pc-web-detailed-design.md) 和 [PoC 计划](pc-web-poc-plan.md)。

### 11.1 浏览器存储边界
- IndexedDB 与 OPFS 都受浏览器 origin 配额、设备空间和用户清理策略影响；不能视为永久存储。
- 应调用 StorageManager.estimate() 监测使用量，并请求 StorageManager.persist()；persist 请求可能被拒绝，必须兼容拒绝结果。
- 无痕模式、浏览器清理站点数据、设备损坏和低磁盘空间均可能导致本地数据丢失。
- 核心私人数据不得作为自动腾空间时的可清理缓存；空间不足时应停止新导入/缓存并提示用户。
- 本地数据主存储必须与可重下载的公共书籍资源缓存分层。

### 11.2 数据库选型方向
- 首选 PoC 为 SQLite WASM + OPFS，单写入 Worker；IndexedDB 为对照和回退候选。
- 该建议基于关系约束、复杂查询、来源追溯和一致性快照需求，不是实测结论。
- OPFS 仅在 Worker 环境可用；SQLite 不同 VFS 对浏览器版本、并发连接、锁和部署响应头存在差异。
- 不能将“浏览器支持 OPFS”直接等同于“SQLite 指定 VFS 在该浏览器可靠”。

### 11.3 加密边界
- OPFS / IndexedDB 本身不提供应用级端到端加密。
- 服务器备份必须在客户端加密；独立恢复凭证用于解包数据集备份密钥，不能依赖账号密码。
- 本地数据库应用级加密仍需独立验证；若本地明文存储，必须如实说明依赖浏览器配置文件和操作系统账户保护。
- Web Crypto API 需要安全上下文；生产环境必须 HTTPS。

### 11.4 备份和清除
- 首次备份为全量；后续增量绑定已确认父备份；定期全量检查点周期由 PoC 决定。
- 分块加密使用 AES-GCM，每块独立 nonce；AAD 绑定数据集、备份、块序号和 schema 版本。
- 服务端只校验密文哈希和 manifest，不解密。
- 清除墓碑必须拦截全部下载、恢复授权、预签名 URL、分块上传完成和重新关联路径；并发清除优先。
- 恢复先进入临时数据区，校验、解密、迁移成功后再原子切换；不得覆盖当前本地数据。

### 11.5 验证状态
浏览器存储选型、崩溃恢复、配额、Web Crypto、恢复凭证、增量备份、清除竞态均未通过本项目 PoC。文档中的方案属于待验证设计，不能表述为已实现端到端加密或可靠备份。
