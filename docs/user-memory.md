# 用户认知记忆与读书笔记机制

## 1. 目标

知行长期保留用户在阅读中的思考过程，并帮助用户看到观点如何补充、修正、冲突和演变。

必须区分：
- 原始对话：用户和 Agent 实际说过什么，是事实依据。
- 读书笔记：对原文、讨论和观点的结构化整理。
- 认知记忆：Agent 从用户表达中识别出的长期观点、问题、假设和认知关系。

认知记忆是派生数据，不能替代原始对话。

## 2. 自动识别原则

不设置收藏动作，不要求用户手动标记重点。Agent 根据对话内容自动识别潜在认知价值。

识别信号包括：独立观点或判断、质疑或反驳作者、联系现实经验、反复追问、认知冲突、观点变化和新的抽象总结。简短但重要的表达也应识别；讨论频率和篇幅不是唯一标准。

系统不应因为用户说得多就机械地产生大量重复记忆。

## 3. 记忆数据结构

每条认知记忆至少包括：
- memory_id、memory_type、content
- source_message_ids
- book_revision_id、structure_node_id、citation_ids
- reading_round_id、created_at、updated_at
- status：current / historical / unresolved
- evolution_relation：supplement / revise / conflict / overturn / extend
- previous_memory_id
- extraction_model_version、review_confidence

无法确认来源的推断不得作为用户明确观点保存。

## 4. 认知演变

- 补充：新观点增加条件、例子或细节，旧观点仍成立。
- 修正：新观点调整旧观点的适用范围或关键判断。
- 冲突：新旧观点暂时并存，尚未明确取舍。
- 推翻：用户明确表达放弃或否定旧观点时，才建立推翻关系。
- 延伸：新观点在旧观点基础上形成更高层抽象或新的应用。

例如：
- 一刷：信息越充分，决策越准确。
- 二刷：关键是识别哪些信息影响决策。
- 三刷：决策能力核心是识别关键变量。

三条记录都保留，并通过演变关系连接。不得仅凭一次措辞差异推断用户改变立场。

## 5. 记忆召回

- 当前讨论：优先召回本书、当前章节和当前主题相关的少量记忆。
- 本书复习：可按阅读轮次查看认知演变。
- 跨书关联：未来可按用户主动提出的主题检索其他书籍记忆，且必须区分不同作者观点与用户观点。
- 不把完整认知档案默认发送给模型；只传输当前任务所需的最小片段。

## 6. 笔记呈现

建议提供作者观点、我的理解、讨论问题、讨论结论和认知演变等视角。每项均可追溯到原始消息和原文位置。

用户可编辑、删除笔记。AI 生成内容与用户编辑内容分别记录版本；AI 不得静默覆盖用户修改。

## 7. 数据保留

- 原始 Message、PresentedSource、Citation 是来源事实。
- Note 和 Memory 可重新加工，但必须保留版本和来源关联。
- 上下文压缩只影响模型请求，不删除本地原始数据。
- 认知提取失败不能影响原始消息保存。
- 用户私人记忆存储在本地数据集中，服务器只保存加密备份。
- 管理员不得查看用户私人记忆。


## 结构化抽取与来源门禁（PR #36）

抽取器只输出候选，不直接写入 Memory。候选必须通过以下门禁：

1. `sourceMessageIds` 必须非空、唯一，且全部来自本次提供的同一 Thread 上下文。
2. 每条候选至少关联一条原始用户消息，不能只引用 Assistant 自己的总结。
3. 书籍来源必须使用当前不可变 BookRevision 的结构节点 ID；不允许引用其他版本或未提供的节点。
4. 作者观点必须要求 Book Citation；任何声明需要书籍引用的候选必须至少带一条完整 locator。
5. 单次抽取最多 10 条候选；同一批次标题和内容完全归一化重复的候选必须合并，不得重复输出。
6. 通过来源门禁后，再进入候选价值、置信度和歧义度评估；低价值拒绝，高歧义进入待确认，不直接持久化。

## 六类认知变化

| change_kind | 含义 | 版本规则 | 跨认知关系 |
|---|---|---|---|
| `new` | 首次形成认知 | version=1，previousVersionId=null | 不允许附加跨认知关系 |
| `supplement` | 补充既有认知 | 同一 Memory 追加版本 | 可选 `supports` |
| `correction` | 修正既有认知 | 同一 Memory 追加版本 | 可选 `supersedes` |
| `conflict` | 与另一认知存在矛盾 | 同一 Memory 追加版本 | 必须 `contradicts` |
| `rejection` | 明确否定/撤回既有认知 | 同一 Memory 追加版本 | 必须 `retracts` |
| `extension` | 在另一认知基础上扩展 | 同一 Memory 追加版本 | 必须 `extends` |

`MemoryRelation` 独立记录 fromVersionId、toVersionId、关系类型和来源消息/原文定位。关系不能替代 MemoryVersion 的不可变前后版本链；所有关系必须有来源证据，且不能自指。

当前领域内核已实现抽取结果来源校验、批次重复候选拦截、关系端点校验和六类变化规则。关系的 SQLite 持久化与版本迁移在后续 #26 工作中接入。
