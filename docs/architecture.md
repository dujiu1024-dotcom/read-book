# 技术架构与关键设计
> 当前架构基线；第一阶段入口已确定为 PC 浏览器 Web，采用窄屏单列阅读布局。具体框架和本地数据库仍需验证，不代表已批准开始业务代码开发。

## 1. 总体架构
系统分为用户端、用户本地数据层、服务端和管理员工作台。第一阶段采用 PC 浏览器 Web；未来可评估小程序或原生 App 等入口，但入口替换不得改变领域模型和数据所有权。

## 2. 用户数据本地优先
- 用户设备本地数据库是个人阅读数据的主存储。
- 服务器只保存用户数据的加密备份副本，不作为在线私人数据主库。
- 服务端账号资料、认证关系、公共书籍、BookRevision 和公共知识库属于平台数据。
- 用户阅读和历史讨论优先读取本地数据；不同账号的数据集严格隔离，不提供自动迁移、同步或合并。
- 同一设备切换账号时保留原数据集；只有用户明确选择某个已有数据集后，才允许继续访问。
- 本地数据至少包括书架权益、Thread、Message、原文展示/临时查看记录、ReadingRound、Note、Memory、来源关系和用户设置。
- 具体采用 SQLite、IndexedDB 或平台原生存储，需按目标平台验证容量、事务、加密、文件访问和迁移能力。

## 3. 本地写入与备份
- 用户操作先写入本地数据库并提交事务。
- 每次应用打开/启动时触发备份检查；存在待备份变更时生成一致性快照，本地加密后上传服务器。无变化时不重复上传。
- 当前设备已有本地数据时按变更执行增量备份；该机制只作用于同一设备/数据集，不构成多设备同步。
- 离线或备份失败不得阻断应用启动和本地阅读，待网络恢复后补做。
- 服务端只校验备份包格式、大小、哈希、版本和密文完整性，不解密私人内容。
- 每次成功备份生成独立版本，不覆盖唯一历史备份。
- 备份失败不回滚本地数据；客户端显示最近成功备份时间和待备份状态。
- 恢复先下载至临时区，校验、解密和迁移通过后再导入；不得静默覆盖现有本地数据。

## 4. 加密与恢复凭证
- 用户私人数据在上传前加密，服务端不持有可直接解密备份的明文密钥。
- 加密密钥与账号密码分离；账号注销或密码变更不能使备份失去恢复能力。
- 使用独立恢复凭证/恢复密钥，支持换设备或换账号后恢复。
- 备份标识、下载授权和恢复凭证分离，不能仅凭备份 ID 下载。
- 恢复凭证丢失且不存在其他有效恢复方式时，数据不可恢复；不设置管理员解密后门。
- 算法、密钥派生参数、轮换策略需经安全评审后冻结。

## 5. 账号与数据分离
- Account 代表身份和认证关系，不是用户阅读数据的容器。
- 切换账号不自动迁移、合并或上传旧数据。
- 用户主动通过独立备份凭证下载并恢复数据；不在常规前台显眼展示恢复入口，也不主动宣传注销后恢复能力。
- 新设备首次打开且本地无知行数据时，提示用户是否从备份恢复；不做多设备实时同步。
- 账号注销只删除账号身份、登录凭证和认证映射，不删除本地数据或服务器加密备份。
- 注销后的备份仍可凭独立恢复凭证访问，除非用户另行执行清除个人数据。

## 6. 清除个人数据与软删除
- 用户主动清除个人数据时，客户端删除当前设备上的个人阅读数据。
- 服务器不物理删除、不改写原始备份，不销毁密钥材料；仅将用户关联索引和可用授权软删除/失效化。
- 数据集进入不可用状态后，读取、检索、下载、恢复和重新授权接口均必须拒绝访问；不得由普通流程重新关联。
- 服务器保留的数据不再参与业务处理。

## 7. 离线能力
- 离线可查看已缓存原文、历史对话、笔记、认知记录和已有阅读信息。
- AI 对话、跨章节智能检索及获取未缓存内容需要联网。
- 离线编辑先保存在本地，联网后再执行备份。

## 8. 模型调用与隐私边界
- 本地优先不代表模型推理必然在本地。
- 云端模型调用只发送当前请求所需的最小上下文，不上传整份本地数据库或完整认知档案。
- 用户表达可能随上下文发送给模型服务商，必须在隐私说明中明确告知。
- 服务端日志不得记录完整私人对话或密钥；管理员默认不能访问私人数据。

## 9. 公共书籍与知识库
公共书籍由服务器管理：Book、BookRevision、BookKnowledgeBase、BookStructureNode、BookKnowledgeItem、BookChunk 和 Embedding。同一 BookRevision 的公共知识库可供有权用户复用；私人 Thread、Message、Note、Memory 不进入公共知识库。

## 10. 书籍加工与发布
管理员上传书籍后，系统解析原文、识别结构、拆分论述单元、提取核心思想/概念/论证/证据、建立章节关系并生成质量报告。管理员检查异常、修正并确认发布。公共书籍版本和知识库是不可变版本；修改创建新版本。
云端是公共书籍正式版本和知识库的权威来源；这不代表云端是用户个人数据主库。

## 11. Agent 请求与阅读界面
- Agent 按需获取当前主线原文、相关全书知识、当前用户输入和少量相关历史认知。
- 不把整本书或全部历史消息发送给模型。
- 原文在上方可折叠展示，讨论在下方；两者属于同一阅读过程。
- 原文展示完成后等待用户发言，不自动生成问题或推送下一段。
- 用户主动要求继续时，按作者主线获取下一单元；临时查看不修改主线状态。

## 12. 管理员工作台
工作台负责书籍上传、元数据、版本、结构拆分、原文查看、全书知识加工、章节关系、质量报告、异常修正、发布和任务监控。不得提供用户私人 Thread、Message、Note 或 Memory 的浏览入口。

## 13. 书籍版本与访问
- 用户加入书架时绑定具体 BookRevision。
- 新版需要单独加入；旧版权益、Thread、知识库和历史引用保留。
- 同一用户数据集对同一 BookRevision 只有一个长期 Thread；不同版本可分别有 Thread。
- 移出书架仅隐藏条目，不删除权益或阅读历史。

## 14. 当前待验证
- PC 浏览器 IndexedDB/OPFS 或 SQLite WASM + OPFS 的容量、事务、持久化、配额和加密能力。
- 本地加密库、恢复密钥安全存储和密钥轮换。
- 启动时备份检查的性能、增量备份、历史保留和下载授权。
- 云端模型服务商的数据处理与留存条款。
- 不同设备恢复同一备份后的分叉处理。
- 长文本原文展示、折叠区和讨论区的实际交互表现。

- [PC Web 窄屏阅读交互规范](pc-web-interaction-spec.md)

当前技术判断（待 PoC，不是最终选型）：
- 首选验证 SQLite WASM + OPFS，采用单写入 Worker、数据集互斥锁和多标签页协调。
- IndexedDB 作为对照与回退候选，不允许两套数据库同时成为可写主库。
- 主测浏览器为当前稳定版 Chrome / Edge；Firefox / Safari 先进入兼容性评估。
- OPFS、IndexedDB 均不等于应用级加密；备份必须在客户端使用独立恢复密钥加密后上传。
- 本地数据库是否应用级加密与服务器备份加密是两个不同问题，仍需安全评审。
- 任何浏览器持久化能力都不能替代备份；必须处理配额、清理、损坏和恢复。

对话生成补充：
- 用户消息先落本地。
- 服务端 GenerationJob 仅承担短暂生成任务和最终结果交付，不成为私人历史主库。
- 最终 Assistant Message 由客户端写入本地；断线后按 generation_id 查询最终结果。
- 生成任务服务端暂存内容需要短 TTL、访问隔离和日志脱敏，具体期限待隐私评审。

以上为详细设计基线，IndexedDB/SQLite、密钥管理、备份和流式恢复均未通过本项目 PoC。
