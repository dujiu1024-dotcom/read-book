# 知行 PC Web 窄屏阅读交互详细规范

> 状态：交互设计基线草案。产品核心规则沿用已确认决策；具体尺寸、间距和断点须经设计稿与可用性测试验证。
> 目标：PC 浏览器中呈现接近小程序的窄屏单列阅读体验，不把 PC 宽屏多栏作为核心任务前提。

## 1. 页面总体结构

### 1.1 布局原则
- PC 浏览器页面背景承担留白；核心阅读容器居中显示。
- 阅读容器采用单列纵向流，不在主阅读页面中并排放置原文区和讨论区。
- 原文区位于讨论区上方；讨论区在下方持续承接用户思考。
- 用户讨论时可以随时回看原文；原文折叠只改变显示，不改变主线位置。
- 阅读、临时查看、复习和讨论保持在同一阅读上下文中，不因为页面切换创建第二条 Thread。

### 1.2 初始尺寸建议

| 项目 | 初始建议 | 说明 |
|---|---:|---|
| 阅读容器宽度 | 390 CSS px | 首轮设计稿基准，不是设备分辨率 |
| 适配范围 | 360–430 CSS px | 通过可用性测试调整 |
| PC 外层最大宽度 | 100% | 阅读容器居中 |
| 左右安全留白 | 至少 16 CSS px | 窄窗口时容器可缩小 |
| 原文正文行高 | 1.7–1.9 | 以中文长文阅读舒适度测试 |
| 正文字号 | 16–18 CSS px | 首轮可读性测试范围 |

390 CSS px 是设计起点，不是已确认的产品常量。浏览器缩放、系统缩放和窗口大小都必须纳入测试。

## 2. 页面骨架
从上至下：
1. 顶部轻量导航：返回、书籍标题、更多操作。
2. 当前书籍信息与阅读轮次状态（不做学习计划或进度监督）。
3. 原文展示区：章节路径、论述单元原文、折叠/展开。
4. 讨论消息流：用户与 Agent 的历史讨论，按时间顺序排列。
5. 输入区：文本输入、发送、停止生成状态。
6. 轻量备份状态入口：仅展示最近备份时间、待备份或失败，不打断阅读。

不要在阅读主页面增加复杂仪表盘、学习计划、理解评分、收藏按钮或强制任务清单。

## 3. 原文展示区

### 3.1 展示规则
- 每次展示一个语义完整的原文论述单元。
- 原文必须标明书名、版本、章节/节和可定位来源。
- 不以固定字数切割；内容切分由书籍加工结果决定。
- 原文区默认展开。
- 用户可折叠原文区；折叠后保留章节路径和展开入口。
- 用户可重新展示已读原文；该行为不改变主线位置。
- 用户因关联问题临时查看其他章节时，显式标记为临时查看；结束后引导回当前主线。
- 不提供选中文字提问能力。

### 3.2 原文区状态
- expanded：显示完整当前论述单元。
- collapsed：仅显示章节/论述单元标题和展开入口。
- temporary_view：临时展示其他章节内容，不修改主线状态。
- review_view：复习已读内容，不创建新阅读轮次。
- 状态切换不得写入主线推进游标，除非用户明确确认推进到下一单元。

## 4. 讨论区
- 用户消息、Agent 回答、引用卡片按时间顺序显示。
- 消息与 PresentedSource/ReadingRound 建立来源关系。
- Agent 引用原文时展示书籍版本、章节和定位信息。
- 用户讨论时原文可折叠，但不自动隐藏。
- Agent 不主动推送问题、测验、下一段原文或提醒。
- 用户直接要求继续而当前单元尚未讨论时，Agent 先确认是否略读；确认略读后才推进。
- Agent 输出失败时保留用户消息，显示可重试状态，不清除原始输入。

## 5. 输入区与生成状态

### 5.1 输入
- 多行输入框，Enter 默认换行；发送按钮提交。
- 明确区分正在生成和已生成完成。
- 发送动作先写本地 Message，再请求服务端生成。
- 断网时允许保存草稿/用户输入到本地，但不假装已收到 Agent 回复。
- 不支持无网络下的 AI 对话。

### 5.2 生成
- 生成中显示停止按钮。
- 流式 token 可增量展示，但正式 Assistant Message 只有在最终结果确认后才落库为 completed。
- 页面刷新后通过 generation_id 恢复状态。
- 取消、失败和自然完成必须有不同状态。
- 用户可在生成期间浏览原文和历史讨论；输入行为按产品策略限制重复并发请求。

## 6. 滚动与定位
- 主页面使用单一纵向滚动容器，避免原文区和讨论区分别滚动造成上下文断裂。
- 新消息到达时，仅当用户当前接近底部才自动跟随；用户向上阅读历史时不强制跳到底部。
- 原文区展开/折叠后，保持用户当前视觉位置，避免页面突然跳动。
- 引用回跳定位到原文论述单元或 PDF 页/EPUB 锚点；若精确锚点失效，回退到章节并展示引用文本。
- 临时查看结束后提供“回到当前阅读位置”动作；不自动更改主线。

## 7. PC 输入与键盘行为
- 支持鼠标、键盘和触控板。
- 不要求用户使用快捷键才能完成核心操作。
- Enter 换行；发送按钮明确提交；可选 Ctrl/Cmd + Enter 作为快捷发送，但需提供可发现提示。
- Tab 顺序与视觉顺序一致；焦点样式清晰。
- Esc 只关闭弹层/菜单，不得清除用户输入或退出阅读。
- 浏览器缩放 80%–200% 下核心布局不溢出；浏览器窗口缩小时容器自动适配。

## 8. 响应式断点原则
- 不按设备型号判断；按可用内容宽度布局。
- 视口宽于阅读容器时居中并保留背景留白。
- 视口窄于容器时容器宽度变为视口减去安全留白。
- 任何宽度下都保持单列阅读结构。
- 管理员工作台可以使用桌面多栏，但与用户阅读界面分离。

## 9. 无障碍与可读性
- 正文与背景对比度满足 WCAG AA 目标。
- 正文字号首轮以 16–18 CSS px 测试。
- 章节标题、正文、引用和 AI 解释使用明确层级。
- 可通过键盘完成展开/折叠、发送、停止、引用跳转和主要导航。
- 不仅用颜色表达备份、生成和错误状态。

## 10. 可用性测试任务
1. 用户打开一本书并阅读当前原文单元。
2. 折叠原文后讨论，再展开回看。
3. 用户滚动查看历史讨论，新消息到达时不被强制拉到底部。
4. 临时查看其他章节并回到主线。
5. 浏览器窗口缩小、放大和缩放后仍可阅读。
6. 用户发送消息、停止生成、断网、刷新后恢复最终结果。
7. 备份待处理状态可被理解，但不打断阅读。

通过标准不以“页面看起来像小程序”为唯一依据，而以原文阅读连续性、讨论可追溯性和主线不被打断为准。
