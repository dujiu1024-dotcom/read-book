# 产品原则与功能边界

## 1. 最高原则

> 用户通过与 Agent 对话来读书。Agent 不管理阅读过程，只参与阅读和思考。

其他功能均为这一原则的副产品。任何新增能力都必须回答：
1. 是否提升对话质量？
2. 是否帮助 Agent 更准确地理解书籍或用户？
3. 是否增加用户操作负担？

不能提升核心对话体验的功能，第一版不做。

## 2. 产品定位与核心阅读方式

知行不是电子书阅读器、读书管理工具或学习计划工具，而是以书籍为知识来源、以 Agent 引导原文精读为核心交互的阅读产品。目标是帮助用户啃难啃、有思想深度和复杂论证的书，而不是替用户总结浅显内容。

- 用户通过与 Agent 对话读书；Agent 不管理阅读计划、打卡或提醒，只参与阅读和思考。
- Agent 按作者原有章节结构和论述逻辑，逐段提供原文。先让用户阅读、理解、复述、提问或质疑，再由 Agent 讲解、讨论和辩论。
- 原文是阅读主体；AI 总结和解释是辅助，不得一开始就替用户把原文嚼碎。
- 按语义完整的论述单元呈现，不机械按固定字数切割。
- 不提供阅读器、选中文字提问或用户跳过当前主线内容的能力。
- 允许略读：用户已经理解且没有深入讨论意愿时，Agent 可简要交流后推进。
- 支持重新展示已经读过的原文，也支持因讨论需要展示其他章节或后续原文；这不改变主线位置，也不构成跳读。
- 用户可以随时复习已读内容。复习不创建新主线、不改变当前阅读轮次。
- 一本书只有一个长期 Thread；完成整本书后，用户可选择开启新一轮阅读，历史对话和笔记全部保留。
- 用户端保持简单对话交互；书籍结构、检索、上下文组织和记忆在后台完成。

## 3. 用户端（手机端）

### 3.1 书城
- 浏览、搜索书籍，查看封面、书名、作者、简介、版本、译者和出版社等信息。
- 书籍仅由管理员上传、加工并发布；用户不能上传书籍，也不通过用户需求提交形成入库通道。
- 管理员发布的书籍默认均为适合精读的书籍，不再由 Agent 判断是否值得精读。
- 用户自主将书籍加入书架；加入后获得永久访问权限。商城下架不影响已加入书架的书籍。
- 管理员负责线下处理书籍来源及授权事项，产品不将版权审核设计成用户端流程。

### 3.2 书架
- 展示用户加入的书籍。
- 用户移出书架采用软删除/隐藏，不删除书籍权益、Thread、Message、Note、Memory 或其他历史数据。
- 用户重新加入时恢复原有访问关系和阅读历史。
- 点击书籍进入该书唯一长期对话。
- 不因章节、主题、日期或阅读轮次创建第二条主线。

### 3.3 对话
- 一本书一个长期对话。
- 纯文字交流，必要时支持基础 Markdown。
- 基础能力：连续消息、流式输出、停止生成、重新生成、自动保存、历史浏览。
- 不做群聊、消息线程、消息引用、多角色切换和复杂阅读模式。
- Agent 根据用户意图自然完成解释、深入讨论、质疑论证、联系现实、验证理解、比较观点和回顾总结。
- 用户准确理解作者但反对作者，仍然属于高质量阅读；不以赞同作者或 AI 作为理解正确的标准。

### 3.4 我的
- 个人资料。
- 按书籍查看 AI 从对话中自动整理的读书笔记，可复制并追溯原始聊天与书籍依据。
- 统计只作为信息展示，不形成任务或目标；有效阅读时长不能简单按页面打开时间计算。
- AI 整理不能覆盖用户原始观点。

## 4. 管理端（PC Web）

- 书籍管理：上传、元数据识别、版本匹配、章节解析、质量检查、索引构建、来源与授权记录、上下架。
- 书城管理：分类、标签、封面、简介、推荐排序和搜索展示。
- 用户需求管理：待处理、处理中、已上架、无法满足。
- 用户管理：账号、状态、书架数量、额度和套餐。
- 平台配置：模型供应商、API 配置、Agent 行为规范、成本和额度。
- 管理员默认不得查看用户私人聊天、原始观点和个人笔记；权限严格隔离。

## 5. Agent 规范

第一版只有一个默认 Agent：阅读导师。能力随用户意图切换，不向用户暴露复杂角色系统。

作者观点必须区分：
1. 作者原文：确实出自原著，提供出处。
2. 作者思想推演：基于作者理论的推导，明确标注为推演。
3. AI 模拟回答：明确标注模拟性质，不得冒充作者真实说过的话。

理解作者与是否认同作者是两个独立维度。保留用户质疑、反对和未解决问题。

## 6. 长期对话与记忆

- 原始聊天记录、原文展示记录和阅读历史长期保存；上下文压缩不能覆盖或删除原始数据。
- 原文独立存储，不把整本书塞入聊天历史。
- 每轮动态组织最近消息、当前主线位置、相关原文、相关历史讨论、用户认知记忆和 Agent 规范。
- 旧对话按需检索；摘要和结构化记忆必须可回溯原始消息。
- Agent 自动识别有价值的用户表达并沉淀，不要求用户主动收藏；产品不设置收藏动作。
- 不把用户推测记为事实，不把 AI 观点记为用户观点。
- 用户观点变化应保留演变过程，不覆盖旧观点。
- 上下文压缩只压缩模型调用时需要携带的上下文；原始消息、笔记、认知记录和来源关系完整保留。

## 7. 自动读书笔记与认知演变

- 所有对话自动保存。
- Agent 自动判断哪些用户表达具有认知价值，自动提炼读书笔记；不设置收藏按钮，也不要求用户手动标记重点。
- 讨论频率和篇幅是重要信号，但不是唯一标准；简短而有独立判断、认知冲突或观点变化的表达也可能非常重要。
- 笔记至少区分：原文/作者观点、用户理解与观点、AI 整理、AI 解释、问题与讨论结论。
- 用户可以编辑、删除笔记；AI 不得静默覆盖用户编辑。
- 每条重要记录保留原始消息、书籍版本、章节/原文定位、时间、阅读轮次和观点状态。
- 认知演变通过新旧观点的关联呈现，区分补充、修正、冲突和推翻；旧观点不被覆盖。
- 认知演变作为后台能力，前台融入读书笔记，不强制用户逐条确认，也不为了展示功能而虚构变化。
- 笔记提供书籍理解、个人认知和认知演变等视角；可从笔记追溯原文和对话。

## 8. 书籍内容管理与访问权益

- 书籍来源及授权事项由管理员在线下自行处理，不作为用户端操作流程。
- 管理员上传并发布的书籍进入统一书籍库；商城状态与用户已获得的访问权益分离。
- 用户加入书架即获得永久访问权限；商城下架不影响已获得的访问权限。
- 用户移出书架采用软删除，不做普通业务数据物理删除；历史对话、笔记和认知记录继续保留。
- 书籍版本更新不得破坏历史引用；历史 Citation 固定到具体 BookRevision。


## 9. 数据长期保存原则

- 知行将书籍、对话、笔记和认知记录视为长期资产。
- 云端是正式数据权威；客户端仅缓存和暂存，不承担唯一保存职责。
- 用户移出书架、商城下架或阅读轮次结束均不得触发历史数据删除。
- 软删除必须保留关联关系和恢复能力；普通业务流程不执行物理删除。
- 需要建立备份、恢复、数据完整性校验和操作审计机制。
- 用户私人数据与公共书籍知识库严格隔离；管理员默认无权查看用户私人对话和笔记。
