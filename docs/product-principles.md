# 产品原则与功能边界

## 1. 最高原则

> 用户通过与 Agent 对话来读书。Agent 不管理阅读过程，只参与阅读和思考。

其他功能均为这一原则的副产品。任何新增能力都必须回答：
1. 是否提升对话质量？
2. 是否帮助 Agent 更准确地理解书籍或用户？
3. 是否增加用户操作负担？

不能提升核心对话体验的功能，第一版不做。

## 2. 产品定位

知行不是传统电子书阅读器、读书管理工具或学习计划工具，而是以书籍为知识来源、以长期对话为核心交互的阅读 Agent。

- 打开一本书，就是打开该书唯一的长期聊天窗口。
- 退出对话即离开；再次打开时恢复原聊天记录，由用户自行决定接下来聊什么。
- 不询问上次读到哪里，不自动续读，不管理阅读进度。
- 不做阅读计划、打卡、每日任务、主动提醒或催促。
- 前台保持简单的一问一答；复杂检索、上下文组织和记忆在后台完成。

## 3. 用户端（手机端）

### 3.1 书城
- 浏览、搜索书籍，查看封面、书名、作者、简介、版本、译者和出版社等信息。
- 用户自主将书籍加入书架。
- 用户可提交想读书籍需求；管理员负责处理、审核来源和上架。
- 用户不承担上传、管理书籍文件的职责。

### 3.2 书架
- 展示用户加入的书籍。
- 可有简单的个人整理标签，但不扩展成阅读进度管理系统。
- 点击书籍直接进入该书唯一长期对话。
- 不因章节、主题或时间变化自动创建新会话。

### 3.3 对话
- 一本书一个长期对话。
- 纯文字交流，必要时支持基础 Markdown。
- 基础能力：连续消息、流式输出、停止生成、重新生成、自动保存、历史浏览。
- 不做群聊、消息线程、消息引用、多角色切换和复杂阅读模式。
- Agent 根据用户意图自然完成解释、深入讨论、质疑论证、联系现实、验证理解、比较观点和回顾总结。
- 用户准确理解作者但反对作者，仍然属于高质量阅读；不以赞同作者或 AI 作为理解正确的标准。

### 3.4 我的
- 个人资料。
- 按书籍查看 AI 从对话中自动整理的读书笔记，可复制并追溯原始聊天与书籍依据。
- 统计只作为信息展示，不形成任务或目标；有效阅读时长不能简单按页面打开时间计算。
- AI 整理不能覆盖用户原始观点。

## 4. 管理端（PC Web）

- 书籍管理：上传、元数据识别、版本匹配、章节解析、质量检查、索引构建、来源与授权记录、上下架。
- 书城管理：分类、标签、封面、简介、推荐排序和搜索展示。
- 用户需求管理：待处理、处理中、已上架、无法满足。
- 用户管理：账号、状态、书架数量、额度和套餐。
- 平台配置：模型供应商、API 配置、Agent 行为规范、成本和额度。
- 管理员默认不得查看用户私人聊天、原始观点和个人笔记；权限严格隔离。

## 5. Agent 规范

第一版只有一个默认 Agent：阅读导师。能力随用户意图切换，不向用户暴露复杂角色系统。

作者观点必须区分：
1. 作者原文：确实出自原著，提供出处。
2. 作者思想推演：基于作者理论的推导，明确标注为推演。
3. AI 模拟回答：明确标注模拟性质，不得冒充作者真实说过的话。

理解作者与是否认同作者是两个独立维度。保留用户质疑、反对和未解决问题。

## 6. 长期对话与记忆

- 原始聊天记录长期保存，压缩摘要不能覆盖或删除原始消息。
- 原文独立存储，不把整本书塞入聊天历史。
- 每轮动态组织最近消息、相关原文、相关历史讨论、用户认知记忆和 Agent 规范。
- 旧对话按需检索；摘要必须可回溯原始消息。
- 不把用户推测记为事实，不把 AI 观点记为用户观点。
- 用户观点变化应保留演变过程，不覆盖旧观点。

## 7. 自动沉淀

后台可从对话中提取：
- 客观知识：作者观点、理论、概念、事实和引用。
- 个人理解：用户如何解释知识及其依据。
- 个人观点：赞同、反对、保留的判断和理由。
- 实践经验：现实应用及结果。

每条重要记录应保留原始消息、结构化内容、书籍与原文关联、时间、观点状态及后续变化。跨书知识图谱可后续考虑，第一版不做复杂可视化。

## 8. 版权与来源

- 管理员上传文件不等于平台获得向所有用户公开提供全文的权利。
- 每本书保留来源和授权审核记录。
- 不默认从网络下载受版权保护的全文。
- 无合法全文来源时，提示合法购买或授权导入。
- 引用应尽量提供必要上下文及章节/页码定位，不编造原文，不将 AI 总结冒充原文。
- 不无条件向用户重新输出整本受版权保护的书籍。
