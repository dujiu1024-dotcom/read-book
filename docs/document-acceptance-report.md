# 知行项目文档验收报告

> 验收日期：2026-11-13。验收范围：main 分支 README 与 docs 目录全部项目文档。验收方式：逐份读取文档目录、章节结构和关键正文，检查产品规则、跨文档一致性、设计可实现性及验证可执行性。
> 结论：产品原则基本齐备；架构和详细设计已有较完整骨架；尚未达到可直接进入正式业务开发的文档验收标准。本报告不是代码或运行时测试结果。

## 2. 已经覆盖较完整的内容

以下原则已有多份文档相互支撑，后续不必重新从零讨论：

1. 用户通过与 Agent 对话读书；Agent 不管理、监督或催促用户。
2. 原文优先，按作者结构和语义完整单元呈现，不以摘要替代原文。
3. 用户主动推进；略读需确认；临时查看/复习不改变主线；全书主线完成后才结束阅读轮次。
4. 一个具体 BookRevision 对应一条长期 Thread，多轮阅读在同一 Thread 累积。
5. 原文区在上、讨论区在下；折叠不改变主线。
6. 不设置收藏动作；Agent 自动识别认知价值；保留认知演变和历史来源。
7. 公共书籍知识库与私人数据隔离；管理员不查看私人 Thread、Message、Note、Memory。
8. BookRevision 版本隔离、加入书架永久权益、下架不影响既有权益、新版单独加入。
9. 用户个人数据本地优先、服务器只保存加密备份、账号与数据分离。
10. 注销、清除个人数据、恢复凭证丢失、离线能力、同设备切换账号等已确认原则。
11. 第一阶段 PC Web、窄屏单列，暂不做小程序和多设备实时同步。
12. 独立 PoC 已覆盖本地存储、备份恢复、文件阅读、流式生成和浏览器兼容方向。

## 3. P0：阻断正式开发的缺项

### DOC-ACC-001：核心数据模型不是数据库实施契约
当前 core-data-model.md 主要是实体字段列表，缺字段类型、必填/空值、默认值、主键策略、外键、唯一约束、索引、枚举、删除语义和迁移规则。

必须补齐：
- 每个实体的字段类型、必填性、默认值、唯一性、索引和外键。
- Thread、Message、PresentedSource、ReadingRound、Note、Memory 的关系约束及删除/保留策略。
- 主线论述单元的稳定 ID、排序、展示状态、讨论状态、略读状态和完成条件。
- Message 状态机：本地待发送、已提交、生成中、完成、失败、取消、重试、重新生成。
- 本地 ID 与服务端 ID 的命名空间、生成方式和碰撞处理。
- 时间字段统一规则，以及本地数据库 schema 与备份包 schema 的迁移兼容矩阵。

验收标准：能够据此建立完整数据库 Schema，并通过迁移、约束、并发和生命周期测试；开发人员不需要自行猜字段含义。

### DOC-ACC-002：核心 API 契约存在版本和路径冲突
core-data-model.md 仍保留旧版 /backups、/recovery/authorize 等 API；pc-web-detailed-design.md 使用 /v1/backups/init、/v1/backups/{backup_id}/parts/{part_no}、/v1/generations 等新路径。身份、消息、书籍访问、加工和生成任务 API 尚未统一。

必须补齐：
- 统一 API 版本、路径、请求/响应 Schema、错误码和认证要求。
- 定义用户端、管理员端、备份端、公共书籍端和生成任务端服务边界。
- ExternalIdentity 登录、绑定、解绑、冲突和注销流程。
- Message 创建、幂等、排序、并发、重新生成、取消和最终结果查询。
- GenerationJob 排队、运行、超时、失败、取消、重试、过期和结果保留状态。
- 书籍版本读取、权益验证、离线缓存和访问拒绝响应。
- 备份会话、分块、断点续传、完成校验、恢复授权和清除墓碑 API。
- 所有写接口的 idempotency_key 与并发控制语义。

验收标准：形成统一 OpenAPI 3.1 文件；Schema 可校验；契约测试覆盖成功、失败、重复请求、越权和并发。

### DOC-ACC-003：备份加密与恢复密钥生命周期未闭环
已提出随机 DEK、KEK、AES-GCM 和独立恢复凭证，但恢复凭证究竟是高熵随机密钥还是用户记忆口令尚未确定；KDF、密钥包装格式、轮换、备份密钥更新、客户端持有方式和恢复凭证丢失边界未冻结。

必须补齐恢复凭证格式与熵、KDF 参数、DEK 生成/包装/轮换、AES-GCM nonce 唯一性、AAD 编码、manifest 明文字段范围、浏览器端密钥缓存、XSS 风险、本地数据库应用级加密决策，以及恢复授权与密钥解包的分离。

验收标准：完成独立安全设计和威胁模型；通过密文篡改、错误凭证、密钥轮换、旧备份恢复、清除墓碑和服务端不可解密测试。

### DOC-ACC-004：书籍包协议未达到机器可执行标准
book-package-ingestion-contract.md 有目录、示例 JSON、字段描述、状态机和验收项，但没有正式 JSON Schema；上传限制、压缩包炸弹、恶意文件、解析沙箱和权限边界不完整。

必须补齐：
- manifest、book、chapters、chunk、local-report 的正式 JSON Schema。
- schema_version 兼容规则、必填字段、类型、格式、枚举和额外字段策略。
- package/revision/attempt/stage/artifact/issue 的关系和幂等规则。
- ZIP 最大包体、单文件大小、总解压大小、文件数、压缩比、路径规范、符号链接和重复文件名限制。
- EPUB/PDF/TXT 格式版本、编码、加密文件、损坏文件和扫描 PDF/OCR 策略。
- 解析器沙箱、资源上限、超时、恶意内容和依赖漏洞处理。
- 分块上传、断点续传、取消、重试、重复提交和完整性校验。
- 本地人工修正与云端重加工结果之间的优先级。
- 版权/授权审核证据、审核角色、拒绝原因和已上架书籍后续撤回流程。

验收标准：真实书籍包可通过 Schema Validator；通过有效包、缺字段、类型错误、路径穿越、压缩炸弹、哈希不一致、重复上传和断点续传测试。

### DOC-ACC-005：阅读主线状态机缺少可实现定义
产品原则和 Agent 交互规范描述了主线规则，但数据模型没有完整表达每个论述单元的用户处理状态。

必须补齐主线单元状态（未展示、已展示、待用户讨论、讨论中、已讨论、已略读、完成）；“讨论过”的最低语义；空消息、表情、短回应、页面离开、断线和重新进入的处理；临时查看后回归主线；重复展示和跨轮次复习记录；旧版本 Thread 主线位置；阅读轮次完成事件。

验收标准：给出状态图和 Given/When/Then 测试；合法交互均有确定状态变化，不依赖模型自由发挥。

### DOC-ACC-006：数据集与账号切换身份边界需澄清
文档同时要求不同账号数据集严格隔离，以及切换账号后用户明确选择某个已有数据集即可继续访问。尚未定义显式选择是仅选择当前账号已绑定数据集，还是允许跨账号重新绑定/恢复。

必须补齐 dataset 与 account 的绑定基数、同设备切换账号时旧数据集发现/隐藏/选择规则、跨账号恢复是否重新输入恢复凭证、原账号是否保留绑定、注销/恢复/清除墓碑优先级，以及防止仅凭 dataset_id 读取其他账号数据的访问控制。

验收标准：形成账号 A/B 同设备切换、注销、恢复、清除和重复绑定的状态矩阵及负向越权测试。

## 9. 最终验收判断

- 产品原则层：基本通过。
- 架构设计层：有条件通过；安全、数据集身份和部署边界需收敛。
- 详细设计层：未通过；数据字典、状态机、API 契约、书籍包 Schema、密钥生命周期尚未达到直接实施标准。
- 验证准备层：有条件通过；PoC 方向完整，但缺逐条可执行用例和量化门槛。
- 正式开发放行：不通过。原因是实现契约和安全边界尚未闭环，不是产品方向不清楚。

本报告只记录审查发现，不自动改变任何已确认产品决策。后续修订不得为了补齐工程细节擅自改变产品原则。
