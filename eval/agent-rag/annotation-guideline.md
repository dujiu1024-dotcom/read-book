# Agent/RAG 评测集人工标注规范（V1）

## 1. 评测目标

评测回答是否有原文依据、是否找到了必要证据、引用是否准确、定位能否回跳，以及 Agent 是否遵守知行的阅读交互原则。语言流畅度不能替代证据质量。

## 2. 评测单位

一条问题记录对应一次独立评测。标注员必须先阅读该题所属样本的全部相关章节，再填写：

- `gold_evidence_chunk_ids`：回答问题所需的最小充分证据集合；跨段题可以有多个 chunk。
- `acceptable_answer_points`：答案必须包含的事实要点，不要求逐字匹配。
- `answerable`：样本是否能支持有根据的回答。
- `expected_locator`：定位题的结构化正确位置；非定位题为 null。
- `question_type`：direct_fact / cross_chunk / concept_explanation / author_counterargument / unanswerable / citation_locator。

禁止把“主题相关”当作“足以支持答案”。如果少一个证据会导致关键结论不成立，应把该证据纳入 gold 集合。

## 3. 问题类型定义

| 类型 | 标注要求 |
|---|---|
| 原文事实 | 答案可由单个原文片段直接支持 |
| 跨段综合 | 必须联合两个或以上片段才能完整回答 |
| 概念解释 | 解释必须遵循作者在当前语境中的定义 |
| 反驳作者 | 先准确复述作者观点，再区分用户反驳或 AI 推演 |
| 书中无依据 | 样本无法回答；必须明确说明证据不足 |
| 引用定位 | 必须定位到正确章节、页码或文本行 |

## 4. 答案与观点来源

评测输出中的 claim 必须标记来源类别：

- `author_fact`：作者明确陈述或可直接归纳的内容，必须有原文依据。
- `user_view`：用户表达的观点，不得伪装成作者观点。
- `ai_inference`：模型推演或外部补充，必须明确标记为推演，不能冒充书中事实。

Groundedness 由人工审阅每条 author_fact claim 的支持情况。评测脚本只汇总人工字段 `human_adjudicated_supported`，不使用模型自评冒充事实核验。

## 5. 标注流程与分歧处理

1. 标注员独立阅读样本并标注证据 ID、答案要点和定位。
2. 第二名标注员复核所有跨段、反驳作者和无依据问题。
3. 分歧必须记录理由；由仲裁者决定最终 gold，不得静默覆盖原始标注。
4. 每次修订记录数据集版本、标注人、日期、变更原因。
5. 评测题不得只根据模型生成的答案反向编写证据。

## 6. 样本来源和版权

当前仓库内的 corpus 是项目自行编写的**合成测试夹具**，没有复制真实书籍内容，不代表真实 EPUB/PDF/TXT 样本，也不满足 Issue #6 的真实书籍样本验收项。

后续真实样本必须逐本登记：
- 来源名称、作者、出版信息、获取 URL 或授权文件；
- 版权状态和允许的内部测试用途；
- 原始文件 SHA-256、文件格式、版本和采集日期；
- 是否为扫描 PDF、是否 OCR、解析器和版本；
- 是否允许将原文片段提交到公开仓库。未获许可时，只保存哈希、定位和受控私有测试数据，不把全文推送到公开仓库。

不得仅因作品年代久远或可在线下载就自行认定可公开复制。真实样本进入评测前，必须完成版权/授权核查。

## 7. 当前夹具边界

当前三组 fixture 分别模拟 EPUB 结构定位、PDF 页码/栏位定位和 TXT 行号定位。它们只验证 JSONL 契约、评测脚本和定位字段的可计算性；不证明 EPUB/PDF/TXT 解析器质量。
